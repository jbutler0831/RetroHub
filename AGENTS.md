# Instructions for coding agents

RetroHub is shared by two people (Jor-el, the author, and J-Star) through
`github.com/jbutler0831/RetroHub`. These rules apply to every coding agent (Codex, Claude Code,
ChatGPT and others) working on it. If a rule and a request conflict, stop and ask.

## Git and GitHub

- **Never push to `main`.** Work on a feature branch (`<name>/<topic>`, e.g. `jstar/controller-test`)
  and open a pull request.
- **A person approves every push**, feature branches included. Show the diff summary and the check
  results, then wait.
- **No force pushes**, and no other destructive remote operation: deleting branches or tags,
  rewriting published history, `git push --mirror`.
- **No merges by agents.** A person reviews and merges every pull request.
- **Don't add, remove or change Git remotes** without explicit approval.
- **Start from the latest `main`:** `git fetch origin` and branch from `origin/main` before
  beginning a feature, and rebase or merge `origin/main` before asking for review.
- **Stop and report** unexpected divergence (local and remote histories that don't share commits,
  a branch that moved since you fetched it) or merge conflicts. Don't resolve them silently.
- **Don't change repository settings**, branch protection, collaborators, secrets or releases.

## What never goes in a commit

- Credentials of any kind: tokens, `.env` files, keys, certificates, signing identities.
- Games, BIOS or firmware files, save files, or anything from someone's game library. The test
  library is generated by `mac/scripts/make-test-library.swift`, which writes its own test ROM.
- Build output: `mac/.build`, `mac/build`, `desktop/dist`, `node_modules`, app bundles, `.zip`/`.dmg`.
- Personal settings: Xcode user data, editor folders, preference plists, logs.
- Files unrelated to the change. Review `git status` and `git diff --staged` before every commit.

## Before asking for a push

Run the checks for what you changed and report the results, failures included:

```sh
# Mac app (Swift Package, macOS 14+; no Xcode needed)
cd mac
swift build                                   # 0 warnings expected
swift build -Xswiftc -strict-concurrency=complete
"$(swift build --show-bin-path)/RetroHub" --self-test
scripts/dev-ui-check.sh                       # window checks; needs the Mac's screen, about a minute
INSTALL=0 ./build.sh                          # universal release build, without installing it

# Windows/Linux/Raspberry Pi app (Electron)
cd desktop && npm ci && npm start
```

Checks that need a person (a controller, an emulator, VoiceOver) stay "unverified" until that
person confirms them. Don't report them as passed from simulated input.

## Keeping the developer's own setup safe

- **Build from a `git clone`**, not a downloaded ZIP. macOS marks every file from a browser download,
  and running `./build.sh` from such a copy shows "cannot be opened because the developer cannot be
  verified", then waits for an answer. Don't remove the mark, choose Open Anyway, or run the script
  with `bash` to get past it: clone the repository instead.
- Run the Mac app as **RetroHub Dev** (`mac/scripts/dev-run.sh`): its own bundle ID, settings and
  test games folder. Don't open `mac/build/RetroHub.app`, which uses the real settings and creates
  `~/Games`.
- Don't install software, change emulator settings, or touch `~/Games`, `~/Applications` or system
  settings without asking first.
- Keep both apps' systems and emulators in step: `mac/Sources/RetroHub/Systems.swift` and
  `desktop/src/systems.js` describe the same catalog.
